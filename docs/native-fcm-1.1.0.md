# تطبيقَا التوصيل 1.1.0: FCM وواجهات الهاتف

## ما تغيّر

أُبقي TWA واختيار Chrome، والحزمتان `app.hhyyw.admin` و`app.hhyyw.captain`. أضيف Firebase Messaging إلى Android وقناة postMessage موثوقة بين الموقع والغلاف. تحتاج القناة علاقة `delegate_permission/common.use_as_origin` في ملف Asset Links المنشور، بالإضافة إلى علاقة فتح الروابط السابقة. البصمة الحالية محفوظة دون تغيير.

الموقع داخل APK يستخدم `native=1` وينتظر قناة Android؛ لا يعلن نجاح FCM اعتمادًا على إذن المتصفح أو اشتراك Web Push. يعمل Web Push في المتصفحات كما كان. بعد نجاح ربط FCM يُزال سجل Web Push الخاص بالجهاز والحساب الحالي لتفادي الإشعار المكرر.

الربط يستعمل جلسة المستخدم الحالية مرة واحدة داخل القناة الموثوقة. يتحقق خادم Supabase من JWT ومن صلاحية الإداري الكامل أو هوية الكابتن، ويحدد صاحب الجهاز بنفسه. لا يُحفظ JWT في Android. يبقى سر تثبيت عشوائي محلي، ويُحفظ ملخص SHA-256 له في الخادم لدعم تحديث FCM token والفصل دون جلسة دائمة. جداول الطلبات والدفعات وسياسات صلاحياتها لا تتغير.

كل ربط حساب له `binding_id`. تُرفض رسالة قديمة من حساب سابق، حتى إن بقيت في طابور FCM. الخروج يمسح الربط المحلي والإشعارات فورًا؛ تعيد WorkManager محاولة الفصل بالخادم عند عودة الاتصال. تحديث token لا يعيد ربط حساب خرج من التطبيق. يتجاهل الإرسال حسابات الإدارة التي فقدت صلاحياتها والكباتن الموقوفين، ويحذف token فقط عند رد Firebase المؤكد `UNREGISTERED`.

الرسائل من نوع data-only وبأولوية عالية، وتعرضها `DeliveryMessagingService` بعد التحقق من الربط. الضغط يفتح التطبيق الصحيح، ثم الطلب المحدد إن وُجد؛ يخضع جلب الطلب لصلاحيات الحساب حتى لو كان خارج أحدث الطلبات المحملة. روابط الإشعار محصورة بالموقع والتطبيق المناسب، وبيانات الخرائط تُعرض دون السماح بحقن HTML أو روابط JavaScript.

## الهاتف والكمبيوتر

التغييرات البصرية الجديدة محصورة في `max-width:719px`: بطاقات للسجلات البسيطة، أزرار 44–48px، حقول كتابة بحجم 16px، عناوين واضحة لبيانات الطلب، أرقام بلوحة مفاتيح مناسبة، وقوائم سفلية قابلة للتمرير فوق لوحة المفاتيح. تُخفى الملاحة السفلية مؤقتًا عند فتح لوحة المفاتيح. بقيت قواعد الكمبيوتر الأصلية. تقارن اختبارات المتصفح بكسلات شاشات الكمبيوتر بالمصدر المرجعي.

## إعداد Firebase والتوقيع

المشروع: `health-beauty-e8abc`. ملف `android/app/google-services.json` المحلي يتضمن التطبيقين، ولا يُرفع تلقائيًا إلى Git. يحتاج CI إلى سر `GOOGLE_SERVICES_JSON` يحتوي الملف نفسه. لا ينشر CI ملف APK ناقص إعداد Firebase. حساب الخدمة الخاص بالخادم لا يدخل APK أو ملفات الموقع.

شهادة التوقيع المطلوبة:

`1E:7B:90:71:94:5F:37:64:AE:71:EC:30:86:70:B6:CF:F4:02:33:2E:80:EA:7A:4D:7D:A0:71:5D:87:24:DF:05`

```powershell
./scripts/setup-android.ps1
./scripts/build-android.ps1 -KeyStorePath 'PATH_TO_EXISTING_KEYSTORE' -PasswordFile 'PATH_TO_PASSWORD_FILE'
```

يبني البرنامج في مجلد مؤقت بمسار لاتيني لأن أدوات Android/Java على Windows لا تدعم مسار المشروع العربي في بعض مراحل البناء والتوقيع. ينسخ المصدر ولا ينقله، ويتحقق من الشهادة قبل التوقيع وبعده، ومن محاذاة APK، ويكتب `artifacts/SHA256SUMS`. لا ينشئ شهادة بديلة ولا يطبع كلمة المرور.

## النشر المطلوب قبل تجربة الهاتف

1. طبّق الترحيل الإضافي `supabase/migrations/20261124180741_native_fcm_devices.sql` على مشروع `jabapvnmfdflysxfxwwf`. لا تُعد تشغيل `schema.sql` القديم فوق القاعدة الحالية؛ فهو لا يتضمن جميع الترحيلات المنشورة سابقًا.
2. أضف سر Supabase باسم `FCM_SERVICE_ACCOUNT_JSON`، بقيمة JSON لحساب خدمة Firebase الذي يملك إرسال FCM في المشروع نفسه. لا تضعه في الواجهة أو Git أو Netlify.
3. انشر الدالتين `native-device` و`send-push` مع إعداد `verify_jwt=false`. تحمي الأولى الربط عبر JWT داخل الدالة، وتحديث الجهاز/فصله عبر سر التثبيت؛ تحمي الثانية عمليات الإرسال بسر `x-push-secret` الحالي.
4. شغّل `npm run build` وانشر مجلد `dist` فقط إلى الموقع الحالي، مع `netlify.toml`. لا تنشر جذر المشروع. ملفات الموقع المسموح بها محددة صراحة في برنامج البناء، ولا تتضمن إعدادات Firebase أو مفاتيح التوقيع أو وظائف Supabase.
5. تحقق من أن `/.well-known/assetlinks.json` على `hhyyw.netlify.app` يضم علاقة `use_as_origin` للحزمتين وبصمة الشهادة الحالية، وأن `/native-push.js` و`/mobile.css` متاحان.

الإصدار الموقّع يفتح الموقع الحالي عن بُعد؛ تثبيت APK وحده لا ينشر الواجهة ولا يفعّل الخادم. لا يمكن ادعاء نجاح FCM الحقيقي قبل خطوات النشر وتجربة الجهاز.

## حالة إعداد الإنتاج — 24 نوفمبر 2026

طُبّق ترحيل الأجهزة على مشروع «محمود»، وتأكد تفعيل RLS ومنع `anon` و`authenticated` من الوصول المباشر، وقصر الدوال على `service_role`. نُشرت `native-device` و`send-push`، وحُفظ `FCM_SERVICE_ACCOUNT_JSON` في أسرار Supabase مع مطابقة بصمته للملف الأصلي. بقيت مفاتيح Web Push الحالية.

نجح اختبار OAuth الفعلي وصلاحيات FCM HTTP v1 باستخدام `validate_only` وtoken وهمي لا يصل إلى أي جهاز. نجح أيضًا فحص نقطة Web Push العامة ورفض ربط جهاز بلا JWT ورفض أصل خارجي. هذه الفحوص لا تثبت وصول الإشعار على هاتف حقيقي؛ تتطلب هذه الخطوة تثبيت التطبيقين وتسجيل الدخول وإجراء اختبار الخادم أدناه.

## التحقق

```sh
npm ci --ignore-scripts
npm test
python -X utf8 tests/check_android_notifications.py
npx playwright install chromium
npm run test:browser
npm run test:mobile
npm run build
```

تغطي الاختبارات توقيع OAuth الخاص بالخادم، طلبات FCM المقيدة بالحزمة والربط، رفض الربط دون صلاحية، ملخص سر الجهاز، رفض الوصول المباشر للجدول، تغيير الحساب والخروج وتجديد token، ورفض الروابط الخارجية. اختبارات Android تشمل توجيه الروابط ورفض الرسائل الخاصة بالحساب السابق. اختبارات المتصفح تستخدم بيانات وهمية دون اتصال بقاعدة الإنتاج، وتفحص عرضي الكمبيوتر والهاتف بعروض 360/390/430، وإرسال نموذج الطلب، ولوحة المفاتيح، وربط القناة والخروج. محاكاة القناة في المتصفح لا تثبت ارتباط Chrome بالتطبيق المثبت على الجهاز.

على الهاتف الفعلي، اختبر كل تطبيق منفردًا ثم التطبيقين معًا:

- ترقية التطبيق الحالي دون إزالته، وتأكيد بقاء بيانات الدخول وإمكانية فتح الطلبات.
- تسجيل الدخول، تفعيل إذن Android من زر الإشعارات، ثم ظهور `Firebase FCM` وربط محفوظ في الفحص.
- تنفيذ اختبار العرض المحلي، ثم **اختبار FCM من الخادم**. قبول Firebase للطلب لا يكفي؛ يجب مشاهدة الإشعار على الهاتف.
- استقبال طلب/ملاحظة/دفعة والجهاز مقفل والتطبيق مغلق، ثم الضغط لفتح التطبيق والطلب الصحيحين.
- الخروج، وإرسال حدث للحساب السابق، والتأكد من عدم ظهور إشعاره. كرّر ذلك بعد تبديل الحساب وعند الخروج دون اتصال ثم عودته.
- رفض الإذن ثم تفعيله من إعدادات Android، وإعادة التشغيل، وتحديث token، واستقلال التطبيقين.
- الكتابة في النماذج ولوحة المفاتيح مفتوحة، وتغيير الحالة وحفظ الملاحظة، والتحقق من عدم تغطية أزرار الحفظ.

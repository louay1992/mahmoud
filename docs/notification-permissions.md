# إصلاح إذن إشعارات تطبيقَي التوصيل

## الأدلة

- لقطة الكابتن: `requestPermission()` يرجع `granted` بينما `Notification.permission` يبقى `default`، ولا يوجد اشتراك، ويفشل `showNotification()` لغياب إذن الموقع. هذا يثبت فشل الإذن الفعلي قبل مرحلة الإرسال من الخادم؛ لا تكفي اللقطة وحدها لتحديد سلوك المتصفح الداخلي بالكامل.
- المصدر الأساسي: `2b6b70562a355f8106cc1b4efd90766967addd5b`، ونشر Netlify الأساسي `6b05c22b57a412cc62b9387a` يشير إلى المصدر نفسه.
- لم يكن AndroidManifest يعرّف `NotificationPermissionRequestActivity`، التي تستخدمها المكتبة المثبتة `androidbrowserhelper:2.5.0` لطلب إذن أندرويد المفوّض.
- كان العامل `/sw.js` مسجّلًا بالنطاق `/`، بينما فلاتر أندرويد تقبل `/captain` أو `/admin` فقط. يعثر AndroidX على خدمة التفويض باستخدام رابط نطاق العامل. كذلك كان التطبيقان يتشاركان اشتراك متصفح واحدًا، فيستطيع حفظ أحد الحسابين استبدال مالك الاشتراك الآخر.
- كان التفعيل يعرض نجاحًا دون انتظار `ensurePush()`، وكانت أخطاء RPC تُهمَل. وجود اشتراك محلي لا يثبت حفظه بالخادم.

## التغيير

- نطاقا العامل وبيانَي الويب هما `/captain` و`/admin`، مطابقان لفلاتر أندرويد. تُستخدم registration الخاصة بالتطبيق مباشرة بدل انتظار registration العامة القديمة.
- أُضيفت شاشة طلب الإذن المعتمدة من المكتبة إلى AndroidManifest. يمر طلب الإذن من زر الموقع عبر مسار التفويض؛ أُزيل الطلب المبكر قبل إنشاء LauncherActivity وطلب استثناء بطارية الغلاف.
- إصدار الغلاف `1.0.1`، ورمز الإصدار `2`. تبقى هوية الحزم وشهادات الربط الحالية كما هي. تحديث APK يحتاج التوقيع بشهادة التطبيق المثبت نفسها؛ مخرجات CI غير موقعة ولا تصلح للتثبيت مباشرة.
- لا يُعلن نجاح التفعيل إلا بعد الإذن الفعلي وإنشاء الاشتراك وحفظه. تُعرض أخطاء HTTP والاشتراك وRPC، وتُحدّ مهلة عمليات التفعيل.
- بعد حفظ الاشتراك الجديد، تُزال سجلات الاشتراك العام المملوكة للحساب الحالي فقط عبر RPC الموجودة. لا يُحذف العامل العام ولا يُلغى اشتراك المتصفح العام، حفاظًا على الحساب الآخر الذي لم ينتقل بعد.
- يفحص التشخيص نتيجة طلب الإذن، والإذن الفعلي، ونطاق العامل، ووجود الاشتراك، ونجاح حفظه بشكل مستقل. نصوص الأخطاء مُرمَّزة قبل عرضها.
- يفتح الضغط على إشعار التطبيق نافذته المناسبة. لكل عامل كاشه، ولا يحذف عامل الإداري كاش الكابتن.
- تنشئ فروع المراجعة مخرجات بناء مستقلة؛ تحديث فرع `apk-build` يقتصر على `main`. تتضمن المخرجات `SOURCE_COMMIT.txt` و`SHA256SUMS`.

## التحقق

```sh
node --test tests/push-client.test.cjs tests/sw.test.cjs
python3 tests/check_android_notifications.py
# يحتاج Playwright وChromium؛ يستخدم حسابات وRPC وهمية ولا يتصل بقاعدة حية:
node tests/notifications-browser.cjs
```

تغطي اختبارات Node تعارض `granted/default`، وانتشار الإذن المتأخر، والرفض، وعزل النطاقين، وفشل الحفظ أو تحميل المفتاح أو الاشتراك، وتزامن طلبات التفعيل، وتفعيل العامل، والانتقال من الاشتراك العام، والخروج، وتوجيه الإشعار.

فحص المتصفح يسجّل عاملين حقيقيين، ويعيد حالة اللقطة، ويختبر عرض خطأ الحفظ بأمان ثم نجاح الحفظ والإشعار المحلي. RPC واشتراكات Push في هذا الفحص محاكاة؛ لا يثبت وصول Push حقيقي أو تفويض أندرويد.

اختبار الجهاز المتبقي: تحديث الغلاف الموقّع، ثم فحص التفعيل والإشعار المحلي وإشعار حقيقي والجهاز مقفل، لكل تطبيق منفردًا ومع تثبيت التطبيقين. يجب أن يظهر إذن `granted`، والنطاق الصحيح، واشتراك محفوظ، ثم وصول إشعار الخادم. لا تُعلن استعادة الإشعارات على الجهاز قبل هذه الجولة.

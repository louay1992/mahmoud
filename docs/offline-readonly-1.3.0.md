# العمل دون اتصال — الإصدار 1.3.0

النطاق المعتمد: **عرض البيانات المحفوظة فقط** في تطبيقَي الإداري والكابتن. لا توجد قائمة عمليات معلّقة، ولا إعادة إرسال عند عودة الشبكة، ولا تغيير لقاعدة البيانات أو معادلات المخزون والمحاسبة.

## الاستخدام

1. ثبّت APK الإصدار 1.3.0 فوق التطبيق الحالي، ثم افتحه مع اتصال وسجّل الدخول.
2. انتظر تحميل الشاشة الرئيسية. افتح التقارير وسجلات المستودعات والفواتير التي تحتاجها قبل فصل الشبكة؛ لا تُنزَّل جميع السجلات التاريخية تلقائيًا.
3. عند انقطاع الاتصال يمكنك تصفح البيانات التي حمّلها حسابك. يظهر شريط «دون اتصال · عرض فقط» مع وقت آخر حفظ، وتنبيه بأن الأرصدة والكميات قد تكون تغيرت.
4. التفاصيل أو صفحات السجل غير المحفوظة تعطي رسالة واضحة؛ غياب النسخة المحلية لا يُعدّ رصيدًا صفريًا أو قائمة فارغة مؤكدة من الخادم.
5. عند عودة الإنترنت استخدم «إعادة الاتصال» أو التحديث. يُراجع الحساب وصلاحياته وتُحمّل البيانات قبل استئناف العمل. لا تُستبدل النماذج المفتوحة ذات التعديلات تلقائيًا.

إنشاء الطلبات، تغيير حالاتها وأسعارها، الدفعات، تسويات المخزون والحسابات تتطلب الاتصال. تظل إعدادات الجهاز المحلية، مثل تفضيل صوت التنبيه، محلية. التعليم كمقروء لا يُرسل دون اتصال.

لا يمكن تسجيل الدخول لأول مرة أو التبديل إلى حساب جديد دون اتصال. تسجيل الخروج يمسح البيانات المحلية الخاصة بالتطبيق ويمنع استعادة الجلسة القديمة حتى إذا فشل طلب الخروج البعيد. لذلك يلزم تحميل البيانات مرة أخرى بعد تسجيل الدخول التالي.

## التنفيذ والحدود

- `offline-data.js/css`: قاعدة IndexedDB مستقلة لكل تطبيق، مرتبطة بمعرّف الحساب المطابق للجلسة المحفوظة. لا تُضاف كلمات المرور أو رموز الجلسة إلى هذه القاعدة؛ تبقى الجلسة ضمن مخزن Supabase الحالي.
- تُحفظ البيانات الأساسية بعد اكتمال مجموعة القراءة كلها بنجاح. فشل إحدى القراءات لا يستبدل النسخة الأساسية بنتائج جزئية. تبقى حدود القوائم الموجودة كما هي: أحدث 300 طلب للإداري و200 للكابتن، وباقي الحدود الحالية.
- التقارير والتفاصيل تُحفظ بمفتاح الاستعلام الكامل، بما يشمل الفلاتر والترتيب والصفحة؛ توجد حتى 120 نتيجة قراءة محفوظة لكل تطبيق. تُحذف الأقدم عند تجاوز الحد. ليست هذه مرآة كاملة لقاعدة البيانات.
- تُستخدم SHA-256 لاكتشاف التلف العرضي في اللقطة والقراءات. هذه ليست مصادقة بديلة للخادم ولا حماية من مستخدم يتحكم ببيئة JavaScript المحلية.
- عند تبدّل الحساب أو تغيّر ملف الصلاحيات الموثق من الخادم تُحذف ذاكرة القراءة السابقة. عند رفض الوصول من الخادم تُغلق النسخة المحلية. لا يمكن كشف تعديل صلاحية من الخادم أثناء انقطاع الإنترنت نفسه؛ العرض يعتمد على آخر وصول مسموح ومحفوظ.
- تسجيل الخروج يضع علامة مسح متزامنة قبل التنظيف غير المتزامن. تُستكمل إزالة قاعدة البيانات في التشغيل التالي إذا قُتل التطبيق أثناء الخروج. تُزال كذلك مفاتيح كشف الإشعارات القديمة الخاصة بالحساب وحالة العودة المحفوظة.
- أوامر الكتابة محمية عند الواجهة وعند تنفيذ طلب Supabase، ولا تُخزّن أو تُعاد تلقائيًا. استثناء التنظيف عند الخروج يسمح بإلغاء اشتراك Web Push الخاص بالحساب عندما تكون الشبكة متاحة.
- فشل التخزين أو امتلاؤه لا يمنع العمل المتصل؛ يظهر أن الحفظ المحلي غير مكتمل. مسح بيانات التطبيق من Android أو إزالة التطبيق يزيل النسخة المحلية.

## فتح التطبيق المغلق دون شبكة

- Android: يحتوي APK على ملفات الواجهة العامة والمكتبة المثبتة محليًا. `OfflineShell` يعرضها عند غياب الشبكة أو فشل الاتصال، تحت **نفس أصل HTTPS** ومن دون فتح Chrome أو Firefox أو تسجيل Service Worker داخل التطبيق الأصلي.
- لا تُعرض من الحزمة استجابات API أو بيانات خاصة أو ملف الإصدار الحي. تُمنع الروابط الأخرى ومسارات التطبيق الآخر، ويظل رفض أخطاء شهادة TLS كما هو.
- عند إعادة الاتصال من الحزمة تُجرَّب الواجهة الحية مجددًا. فشل الاتصال يعيد العرض المحلي بدل حلقة تحميل.
- الويب/PWA: يحفظ Service Worker حزمة عامة مكتملة متحققًا من بصمات كل ملف قبل تفعيلها. يبقي آخر حزمة مكتملة إذا فشل ملف أثناء التحديث؛ لا تُمسح بتحديث الواجهة التلقائي.
- تم تثبيت Supabase JS على 2.119.2 مع ترخيصه، بدل الاعتماد على CDN أثناء الإقلاع.
- أسماء الحزم `app.hhyyw.admin` و`app.hhyyw.captain` وشهادة التوقيع الحالية محفوظة. رقم الإصدار `1.3.0` ورمز Android `6`.

## التحقق

- `npm test` و`npm run test:android-wiring`.
- `npm run test:offline`: SDK الحقيقي، بيانات خادم اصطناعية، IndexedDB وService Worker فعليان؛ إغلاق عملية المتصفح وفتحها دون شبكة؛ جلسة منتهية الرمز؛ استعلام محفوظ مقابل صفحة لم تُحمّل؛ رفض أوامر الكتابة؛ اختلاف الحساب؛ الخروج دون اتصال ومسح اللقطة؛ رفض الصلاحية عند العودة؛ رفض لقطة تالفة؛ فشل تحديث حزمة مع الحفاظ على النسخة المكتملة.
- اختبارات Auth وNative Host وRefresh وWeb Push وDiagnostics، واختبارات الواجهات والمخزون والتقارير والنماذج والحركة بأحجام الهاتف والكمبيوتر.
- اختبارات Android لكلتا النكهتين، بما فيها `OfflineShellTest`: أصل HTTPS ومسار التطبيق ومكتبة SDK، ورفض التطبيق الآخر والخادم ومسارات غير مسموحة.
- البيئة: Windows، Playwright Chromium 159، عرض 390×844 لاختبارات العمل دون اتصال؛ Robolectric API 28 لاختبارات Java. هذه ليست تجربة وضع طيران على جهاز فعلي.

يلزم اختبار النسختين على الهاتف الحقيقي: تحميل بيانات مع الشبكة، تفعيل وضع الطيران، إغلاق التطبيق من التطبيقات الحديثة وإعادة فتحه، قراءة الطلبات والمخزون والتفاصيل المحفوظة، ثم إعادة الشبكة ومراجعة تحديث البيانات والخروج. وصول إشعار FCM جديد يحتاج اتصالًا بخدمات الإرسال؛ مشاهدة الإشعارات المحفوظة متاحة محليًا.

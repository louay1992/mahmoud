# إصلاح الخروج واستعادة الجلسة — 24 نوفمبر 2026

كان مسار الخروج في التطبيقين ينتظر فصل FCM قبل استدعاء Supabase signOut. فشل القناة أو انتهاء مهلة Android كان يرمي خطأ ويترك جلسة الحساب محفوظة؛ ثم يستعيدها boot عند الفتح التالي. كذلك كانت نتيجة signOut تُهمل، وبعض إصدارات مكتبة Auth المحفوظة في كاش المتصفح تُبقي الجلسة المحلية عند فشل إلغائها من الخادم.

يضع الخروج المؤكد الآن علامة محلية خاصة بالتطبيق، ويخفي واجهة الحساب ويمسح حقول الدخول فورًا. تبدأ محاولة فصل الإشعارات والخروج بنطاق local، ثم تُمسح مفاتيح جلسة التطبيق ويُعاد تحميل الصفحة خلال ثانيتين كحد أقصى، حتى لو تعطل الخادم أو غابت قناة Android. لا يمسح ذلك جلسة التطبيق الآخر أو حسابات الأجهزة الأخرى. ترفض صفحة البدء وعملية ربط FCM استعادة الحساب بعد الخروج، حتى إن وصلت كتابة قديمة من عملية تجديد جلسة متأخرة. لا تُرفع علامة الخروج إلا بعد نجاح إدخال بيانات دخول صحيحة.

طلب فصل FCM يبقى محفوظًا محليًا عند غياب القناة، وتُعاد محاولته عند اتصالها وقبل ربط حساب جديد. هذا لا يدّعي فصل Android فعليًا قبل استلام إقراره. إلغاء Web Push المحلي يحدث قبل محاولة حذف سجل الخادم حتى لا يمنع خطأ RPC إيقاف اشتراك المتصفح.

أضيفت اختبارات لفشل الفصل والخادم، والمهلات، واستقلال التطبيقين، وإعادة الفتح مع جلسة قديمة، وكلمة مرور خاطئة، وحساب جديد، وفصل الربط القديم قبل الجديد، وإلغاء نافذة تأكيد الخروج. فحوص المتصفح تستخدم حسابات وSDK وهمية دون الاتصال ببيانات الإنتاج، مع الاحتفاظ بفحوص المطابقة البصرية السابقة. لا يحتاج هذا الإصلاح إلى تغيير غلاف Android أو شهادة التوقيع؛ يُنشر ضمن ملفات الموقع ونسخة كاش v7.

التحقق: `npm test` و`npm run test:auth` و`npm run test:mobile` و`npm run test:browser` و`npm run build`.

مرجع سلوك المكتبة: [Supabase signOut](https://supabase.com/docs/reference/javascript/auth-signout). تحقّق أيضًا من مصدر `auth-js@2.89.0` المستخدم سابقًا: فرع أخطاء الخادم في `_signOut` يعود قبل `_removeSession`، ولذلك لا يعتمد الإصلاح على نجاح الشبكة لمسح الجلسة المحلية.

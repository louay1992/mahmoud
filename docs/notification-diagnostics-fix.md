# إصلاح تعليق فحص الإشعارات — 24 نوفمبر 2026

كانت صفحتا الكابتن والإداري تضيفان خلفية الفحص قبل انتظار `pushClient.inspect()`، وتؤخران رسم النافذة وزر الإغلاق إلى حين وصول النتيجة. عند غياب قناة Android يستغرق الانتظار 15 ثانية، وقد تصل مهلة طلب الحالة بعد اتصال القناة إلى 35 ثانية. كذلك كانت الاختبارات تعطل جميع الأزرار، ومنها الإغلاق، ثم تنتظر فحصًا آخر قبل إعادة رسم النافذة. ظهر ذلك للمستخدم كتطبيق عالق خلف طبقة داكنة.

أصبحت النافذة مشتركة في `push-diagnostics.js` وتُرسم من حالة محلية فورية قبل أي طلب. تحديث الحالة له مهلة مستقلة، ويظل الإغلاق متاحًا أثناء القراءة والاختبارات وحتى أثناء عمليات التطبيق الأخرى. الإغلاق وزر Escape يلغيان انتظار النافذة؛ تُهمل النتائج المتأخرة ولا تُفتح نافذة مغلقة مجددًا. لا يُعاد طلب القراءة عند الضغط المتكرر على تحديث الفحص.

فحص Android لا ينتظر إنشاء قناة غير متصلة، ويعرض غيابها فورًا. عند وجود القناة، يحد طلب الحالة إلى 2.5 ثانية. طلبات الإذن والاختبار اليدوية تفشل برسالة واضحة عند غياب القناة، بدل انتظارها دون نافذة قابلة للإغلاق. لا يُستنتج أن إعداد Firebase غير موجود من مجرد غياب الرد؛ تظهر الحالة غير المعروفة صراحة. أُزيل رقم الواجهة الثابت من عنوان الفحص لأنه لا يثبت إصدار APK المثبت.

تغطي اختبارات المتصفح الجديدة التطبيقين بعرض 390px: ظهور النافذة فورًا، غياب القناة، رد لا يكتمل، انتهاء المهلة، إغلاق أثناء عملية معلقة، حالة busy، زر Escape، وتجاهل الرد بعد الإغلاق. بقيت اختبارات Web Push وFCM السابقة والخروج والمطابقة البصرية للهاتف والكمبيوتر ناجحة. لا تستخدم الاختبارات بيانات إنتاج.

التحقق: `npm test`، `npm run test:diagnostics`، `npm run test:browser`، `npm run test:mobile`، `npm run test:auth`، `npm run build`.

التغيير ضمن الموقع وكاش v8؛ لا يغيّر APK أو شهادة التوقيع ولا يثبت وحده وصول FCM إلى الجهاز. تساعد نتيجة الفحص الآن على متابعة سبب عدم ربط الهاتف.
